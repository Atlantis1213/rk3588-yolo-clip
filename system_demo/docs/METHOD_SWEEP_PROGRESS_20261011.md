## 已完成板端对照

同一官方 ViT-L/14、同一六类文本bank；新144张开发图每类24张，来源与之前360张互斥，
精确224×224像素重复0；不保证语义近重复不存在。另144张锁定测试图尚未参与评估或挑策略。
所有候选的输入FP16位模式与本轮FP16基线完全相同。实际算子表核验通过，混合模型的
24个SDPA为INT8 NPU，完整算子/精度/target签名与KL120基线一致。

KL30/normal30/MMSE30用完全相同的原校准子集，每类5张；因此算法对照应比较这三行。
KL120和MMSE30的数据量不同，不能据两行差异直接归因算法。
RepQ式LN2浮点等价检查最低余弦约0.99999999996，6张最大绝对误差不超过2.59e-5，
但量化分类比KL120少1张。开发集小样本下不能把1–2张差异解释为显著收益/损失。
按照预先规则，浮点折叠的分类结果低于KL120时不追加独立测速；不选择该候选。

每个测速轮次含FP16/KL120/候选的单context all和三context spread，两轮正序/反序，
每配置8秒，host固定FP16输入，初始化和两次并行热身不计入。三context通过context
复制共享权重、独立绑核。以上FPS为CLIP-only聚合完成吞吐，不能当作单张延迟，
也不含YOLO、摄像头、RGA、DMA。未做长期稳定性。

FP16在trash类仅1/24正确、KL为0/24，因此总体精度不仅包含量化问题，还受到
这一固定零样本分类任务自身能力限制。没有根据开发图修改文本模板来制造收益。

## SDK算法记录的额外核查

`algorithm_contract_audit_v2.json`核对了三组实际保存的SDK算法标识、输入文件SHA、
IR、cfg和内部`quant_tab`，不是只看启动时传入的名称。
KL30/MMSE30的可编辑cfg和step1 quant_tab完全一致，但`.data`中的两个算法字段分别
保留KL/MMSE，模型文件及板端输出不同。故不能把这两组差异全都说成“激活范围变化”；
仍需进一步核查SDK在最终编译/权重量化阶段如何使用算法字段。没有声称SDK内部已逐位复现。

## 4060真实CUDA层重建已完成

24个既有MLP下投影，每层500步，原120张校准、每图固定16个token，未读取开发或锁定
测试的像素/激活。采用SDK KL120保存的24,576个实际逐输出通道weight scales/zero points，
固定激活QDQ参数，训练自适应舍入logits，并单独计算nearest/learned的输出偏差补偿。
这是AdaRound式单矩阵pilot，不是完整BRECQ或逐位RKNN QAT。

平均层重建MSE（校准代理）：

- nearest：0.0026002052。
- AdaRound hard：0.0024505236，下降约5.76%。
- AdaRound+bias：0.0023428715，下降约9.90%。

这是层重建误差，不是全模型分类准确率。block12的误差仍约0.027，说明仅调舍入
不能消除所有激活误差，也不能据此认定唯一瓶颈层。
24层权重包SHA/矩阵shape/有限值/固定INT8网格核验通过，最大整数网格误差1.53e-5。
训练包173MB已取回本机；仅bias、仅AdaRound、AdaRound+bias三个完整模型转换及板端
评估已排入下一条串行队列。SDK是否保持训练网格以及最终准确率/吞吐仍待验证。
