# 第二轮 QAT 与首个注意力路径诊断

更新：已将混合FP16融合SDPA的板端均匀化行为在约0.45MB无权重模型上独立复现；
仅让SDPA保留INT8即可恢复query差异。详见 `SDPA_ROOT_DIAGNOSIS_20261010.md`。

## 1. 训练已完成，未部署

4060 完成三组新增各300步的真实CUDA QAT/蒸馏；训练、验证、最终测试来源与首轮
完全相同且互斥，随机种子、batch1、学习率1e-5、固定文本bank、原模型结构及输入尺寸
保持不变。全部从官方原权重重新开始，没有从上一轮失败模型续训。

两组损失消融均只训练102,400个LayerNorm参数：

- KL系数从0.1提高到5，ranking系数仍为0。
- 在KL=5的基础上，加入系数1的教师top1-to-other间隔损失。

排序损失不是验证标签交叉熵：对每张训练图片，以教师得分最高的类别为锚点，
当学生与其它类别的分数差小于教师分数差时才产生惩罚。教师误分类也可能被蒸馏继承。

第三组恢复首轮损失（cosine + 0.1 KL），额外训练已有的最终1024×768投影矩阵，
总可训练参数888,832。没有插入LoRA、额外分类头、缩小网络或改变推理算子。
训练态对投影权重采用带STE的per-channel fake quant，禁止使用脱离梯度的缓存。

| 实验 | 末步特征余弦 | 末步六类准确率 | 末步教师top1一致率 |
| --- | ---: | ---: | ---: |
| 未训练W8A8代理 | 0.786203 | 64.17% | 75.83% |
| 首轮LN，KL=0.1 | 0.807472 | 61.67% | 未记录 |
| LN，KL=5 | 0.800681 | 63.33% | 76.67% |

FP32教师准确率74.17%。各新增实验的准确率最佳checkpoint仍为step0；
余弦最佳为step300。最佳准确率checkpoint按严格大于保存，持平不替换step0。
最后一组梯度有效、矩阵缓存回归通过，CUDA allocated峰值2409.010MiB。
该组训练主循环（含周期验证）140.422秒，不含启动、下载验证、教师缓存等。

结论：投影矩阵提供更好的特征拟合能力，但分类尚未改善；不能当作已解决量化精度。
平均余弦、教师一致率与真实分类不能互相替代。这些均是训练代理指标，尚未导出
QAT ONNX/RKNN，也没有新的板端加速数字。没有使用最终测试集来筛选候选。

权重覆盖集合、provenance、完整300步loss、六次验证、baseline/status均已取回：
`results/remote_4060_20261010/qat_ln_kl5_20261010/`、
`qat_ln_kl5_rank1_20261010/`、`qat_ln_projection_20261010/`。

## 2. 板端异常已缩小到首个注意力相关路径

依照 diagnose 的最小复现/固定输入差分方法，从原FP32 ONNX截取前缀进行定位，
不是把裁剪模型用于部署或宣传模型缩小后的加速。各前缀都对同6张固定输入比较：
ONNX Runtime、RKNN普通FP16模拟器、混合全浮点模拟器，以及两种模型的板端输出。
CPU侧输出与板端输出维度逐一核对后才比较。

| 截取终点 | 普通FP16板端→ONNX余弦 | 混合全浮点板端→ONNX余弦 | 两种板端输出之间余弦 |
| --- | ---: | ---: | ---: |
| ln_pre | 0.999999475 | 0.999999475 | 1.000000000 |
| block0 LN1 | 0.999999265 | 0.999999265 | 1.000000000 |
| block0 注意力+第一条残差 | 0.999997116 | 0.967351324 | 0.967556025 |
| block0 完整输出（含MLP/第二条残差） | 0.999981131 | 0.933262930 | 0.933793646 |

上述各前缀两种模拟器对ONNX余弦均大于0.9999997。
同一固定输入前缀在板端即可复现“模拟器正确、混合路径失真”的核心症状。
比反复做整个24block的校准/120张评估更快，最小复现区域已经包含首个注意力路径。

不能把裁剪图结果当作完整图逐层trace：截取输出会改变融合/编译上下文。
当前未证明唯一错误算子，也未证明就是softmax、LayerNorm或CPU fallback。
范围包括QKV投影/拆分/重排、融合SDPA、输出投影和相邻边界。
保存的IR中有`exSDPAttention`，scale约0.125；存在这个节点不代表其本身就是根因。

前缀混合控制以6张固定验证输入生成临时IR、将所有可映射算子输出设为FP16；
此处仅为编译路线诊断，不是用验证集给生产INT8/QAT候选做校准或调参。
实际训练/量化候选数据隔离仍按训练/验证/最终测试协议执行。

## 3. 有效证据与失败尝试分开保留

- 直接在原opt3 step1 IR的step2改opt0：SDK拒绝配置不一致，未生成模型，
  不算“关闭优化后精度仍失败”。保存于`precision_controls_20261010/all_fp16_io_opt0/`。
- 尝试`op_target={'exSDPAttention':'cpu'}`：普通FP16阶段构建完成，混合step1拒绝
  该key，未形成有效CPU/NPU对照，不算CPU回退已验证或精度已修复。
  保存于`prefix_attn0_sdpa_cpu_control_20261010/`。
- 新opt0注意力前缀从step1开始配置，已完成两种导出路径、模拟器和板端6张测试：
  结果与opt3相同（混合板端→ONNX余弦0.967351）。检查两个step1 IR，均仍包含
  一个`exSDPAttention`。不能声称该实验已移除融合SDPA、或证明所有融合均无影响。
  证据在`prefix_attn0_opt0_control_20261010/`。
- 发现融合SDPA在量化配置里还有`q_matmul`和`q_softmax`辅助项，不是普通节点输出。
  新增两项FP16保护被SDK接受，模型成功导出；但6张板端输出与此前控制逐元素相同，
  平均余弦仍0.967351。不能把cfg仍写INT8直接当作实际内核INT8的证据，也不能
  声称补齐这两项已解决问题。证据在`prefix_attn0_aux_control_20261010/`。

所有诊断使用独立模型目录，Runtime2.3.2以子进程LD_LIBRARY_PATH选择，
没有覆盖生产模型、系统库、driver0.9.6或governor。
