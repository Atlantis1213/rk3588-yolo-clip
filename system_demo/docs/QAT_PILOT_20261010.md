## 首轮方法及范围

- 同架构官方 OpenAI ViT-L/14，224×224，24 blocks，768 维 embedding。
- 原工程历史权重未找到：本轮属于独立官方参考实验，不声称与历史 RKNN 同权重。
- 固定大矩阵、缓存 W8 per-output-channel fake-quant 权重，仅训练全部 LayerNorm
  gamma/beta，共 102,400 参数。没有剪枝、缩小网络、改输入尺寸。
- 使用 RKNN 校准配置的 per-layer 激活 scale/zp；本轮代理全部激活站点找到对应值
  （missing_proxy_sites=0）。LN、GELU、softmax、残差浮点。
- 显式 attention、checkpointing、batch=1、AdamW lr=1e-5、无 weight decay、梯度裁剪1。
- 损失：`1 - cosine(student, teacher) + 0.1 * KL(teacher_text || student_text)`，
  固定六类文本 bank，温度0.07。教师特征缓存后复用其视觉塔作为学生，不同时驻留两塔。
- 120 张校准图片用于训练，120 张验证用于选择 checkpoint，另120张最终测试仅核验
  来源互斥，没有用于训练、调参或本轮评估。无数据增强，遵循原评估的直接resize224、
  RGB标准化、IEEE FP16舍入再转FP32输入。
- 此训练代理不逐位模拟 RKNN：其误差/分类不代表板端最终结果。

FP32教师准确率74.17%。训练主循环（含定期验证）138.157秒；不含下载、教师缓存、
校准及初始验证。CUDA allocated峰值2398.045 MiB（约2.342 GiB），不是进程总显存。

结论：有限步数的归一化微调改善了平均特征方向，但没有改善分类。不能据此宣称
QAT已恢复精度，也不能宣称QAT没有价值或后续不可能改善。

- `best_accuracy_delta.pt`：step0，未训练基线仍为准确率最佳。
- `best_cosine_delta.pt`：step300，余弦最佳，但准确率下降。
- `latest_delta.pt`：step300。

checkpoint为约0.48MB的归一化参数绝对值覆盖集合（代码字段名delta），不是完整模型、
也不是要相加的数学差值。包含源权重SHA、架构、激活参数及验证指标。
加载时应将相应参数覆盖到同SHA官方权重；本轮尚未导出/转换QAT RKNN。

## 同步固定输入诊断

依据 diagnose 的固定输入差分思路，串行比较三个模型、两种核分配和四种受支持输入
提交模式。没有新增技能依赖的项目管理配置，不升级系统Runtime/驱动。

使用每类第一张验证图片共6张，隔离Runtime2.3.2、driver0.9.6。

| 模型 | 对正常FP16平均余弦 | 单核/三核 | host FP32/FP16 | host/native透传 |
| --- | ---: | --- | --- | --- |
| 正常FP16 | 1.000000 | 一致 | 一致 | 一致 |
| 全浮点含IO混合导出控制 | 0.524883 | 一致 | 一致 | 一致 |
| GELU敏感混合含IO | 0.486735 | 一致 | 一致 | 余弦0.948093 |

正常FP16对Torch参考余弦0.999919。错误模型与故意将CHW数据当NHWC提交给正常
模型的结果也不一致，不能用简单布局错配解释异常。

第一版探针的NCHW模式被Runtime normalize明确拒绝，虽然API返回值没有可靠反映
日志错误，其结果全部排除。有效结果来自`layout_core_v2_20261010`；v1只保留诊断记录。

再以子进程选择原系统Runtime2.3.0，对三个模型重复all核、同6张输入；与2.3.2
相比输出逐元素完全一致（max_abs_error=0），没有修改系统库。此结果仅缩小Runtime
版本差异假设，不排除两版本共有问题、driver问题或混合IR/编译变换问题。

不能断言已找到错误算子。下一步重点检查step1 IR到混合导出图的变换、布局与融合；
训练分支则应增强分类/ranking约束并评估训练参数范围，不盲目只增加步数。
